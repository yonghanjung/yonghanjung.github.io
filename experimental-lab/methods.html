Methods & nuisances

Target and meanings

Choose the mean outcome under one intervention (APO) or a difference between two interventions (ATE). A treatment can be one binary variable or an ordered cluster of binary members.

Let A be the whole scalar or ordered treatment tuple, Y the scalar outcome, and C the covariate vector in the verified adjustment witness. Y(a) is the outcome under intervention A=a. APO is E[Y(a)]; ATE is E[Y(a)]−E[Y(a0)], for the population represented by the observed cohort. The following1-versus0 formula is the scalar binary ATE example:

τ=E[Y(1)−Y(0)]

The graph supplies the causal assumptions that make this target identifiable from observational data. Identify checks those graph conditions without data. It does not verify that the supplied graph is true in the real world. Estimate approximates an identified quantity from observed rows.

A nuisance function is an intermediate function learned to compute the final effect. AIPW and Outcome Regression learn outcome means; AIPW also fits balance weights. IPW learns treatment probabilities and derives their inverse weights, without outcome fitting. The target uses the whole cohort, not just treated rows. No rows are trimmed to redefine the target.

Marking a variable Unobserved changes its visibility, not its arrows or mechanism. Random Data runs the full SCM and returns only Observed columns. Identification and data estimation use a separate latent projection: hidden-interior directed paths become directed edges, and each hidden variable's independent noise remains shared by its first Observed descendants. Existing identification and estimator restrictions still apply; marginalization does not make every effect identifiable. See Shpitser (2020), Section 5.2.

Which method actually runs?

The three baseline choices require one binary scalar or ordered binary-cluster treatment, one scalar observed outcome, no factual evidence, and a verified baseline Back-door (BD) or Adjustment Criterion (AC) witness. The adjustment nodes must be observed non-descendants of the treatment. An identification result for Front-door or Sequential does not itself enable these baseline methods.

A failed supported baseline fit remains UNKNOWN, with no estimate. Explicit baseline requests outside scope are UNSUPPORTED. There is no silent fallback. Observed data and encoding

The estimators learn from the selected factual rows. Model references and benchmark truth never enter their fits.

load_data accepts the graph, selected numeric rows and an explicit mapping from each observed node to a column or ordered list of columns. A cluster binds a whole vector without changing the public node's name, dimension, arrows, positions or roles. A covariate cluster must belong to an actually verified baseline adjustment witness and cannot be a treatment descendant. Binary treatment clusters are separately validated joint assignments; unsupported mediator/time/outcome cluster bindings abstain.

Input limits are 1–5,000 rows, at most 100 selected physical columns and 500,000 cells. Duplicate/missing mappings, reused columns, missing values, nonnumeric/nonfinite selected cells and incompatible scalar/binary domains are rejected. Unused text columns can remain in the original file and are excluded before numerical loading. Rows are not silently dropped or imputed.

Nominal covariates retain their codebooks. An explicit categorical_encoding="one_hot" creates every category indicator in a temporary fitting view. It does not impose distances on ordinal-looking codes or turn indicators into new causal nodes. Original data, logical graph and codebooks remain intact. Dense temporary allocation is checked against 100 total columns and 500,000 cells. Continuous or nominal treatment-cluster components and categorical outcomes are unsupported by the current joint-propensity baseline; binary components must be declared explicitly.

For example, a three-level covariate coded 0, 1 and 2 is represented by all three indicator coordinates. estimation_details.inputs.covariates records the exact source-column/equality recipes. Each baseline choice uses only coordinates of its verified witness, not every variable drawn in the graph.

Actual regression inputs and diagnostic coordinates

Every coordinate of the actual verified adjustment witness enters XGBoost. A vector node uses all its ordered bound members. Nominal covariates use the existing full one-hot fit view, retaining every category and logical node. No source row or witness coordinate is dropped. Covariates outside the chosen witness are not automatically added.

XGBoost receives the original finite numeric coordinates, not the former standardized linear-plus-square regression basis. No learned polynomial or RBF expansion is used. With zero real predictors, the helper supplies one explicit constant-zero column and still trains XGBoost.

Separately, raw-coordinate imbalance diagnostics standardize each original witness coordinate by its whole outer-training mean and standard deviation; a standard deviation at most 1e-12 becomes 1. Coordinates constant in training map to zero there. This linear-only diagnostic is not the weight constraint or a new set of fitted features.

The XGBoost outcome nuisance

For each treatment arm, a real XGBoost model predicts the mean outcome from the witness covariates.

The ideal function is m_a^*(c)=E[Y | A=a,C=c]; the fitted m_a(c) approximates it. The implementation uses XGBoost 2.1.4, core DMatrix/train APIs, with only that arm's outer-training rows. Its training-response mean sets base_score. All heldout outcomes and evaluation references are excluded from learning. 

objective = "reg:squarederror"
num_boost_round = 64
max_depth = 3; eta = 0.05; tree_method = "hist"
nthread = 1; subsample = 1; colsample_bytree = 1
reg_lambda = 1; min_child_weight = 5
base_score = mean(training_arm_outcome)

These settings are fixed before evaluation; there is no outcome-based tuning, inner cross-validation or early-stopping selection. Deadline callbacks check after every boosting iteration and after prediction. Multiple conditional-mean output coordinates use one booster per coordinate. Exact finite predictions, settings and training RMSE are returned.

AIPW and OR fit these models only for the requested assignment(s). ATE requires two regimes (four arm/fold fits); APO requires one (two fits). AIPW reuses each fitted mean for its balance constraint and heldout score. IPW does not fit these outcome models; it fits the joint classifier described below. OR never fits weights.

Browser computation uses the official Pyodide 0.29.4 XGBoost 2.1.4 package on the user's device. Native Python pins the same package version. Identify alone does not load XGBoost. Simulator mechanisms and density/particle sampling are separate operations.

Minimum-second-moment fitted-outcome balance

AIPW minimizes weight variability while exactly matching the whole training cohort's fitted arm-specific outcome mean.

For a fixed arm a, let T be the outer-training cohort, N its size, and S its rows with A=a. The fitted prediction gi=ma(Ci) is evaluated on every training row. Define the full-cohort weight Wi=1[Ai=a]wi. It is zero outside the selected arm; positivity applies to the within-arm weights.

minw1N∑i∈Swi2subject to1N∑i∈Swi=1,1N∑i∈Swigi=1N∑i∈Tgi,wi≥ε

The fixed ε=1e-8 is inside the feasible class, making the numerical problem closed and strictly positive on the arm. Strict w>0 without a floor need not attain its infimum. There is no RBF loss, weight ridge penalty, ratio projection, propensity fit or prevalence division in this calculation. The target is the whole training cohort, not the treated cohort.

Exact scalar active-set solver

Center predictions by their whole-training mean t and divide by their whole-training standard deviation s (use 1 when at most 1e-12). Write z=(g−t)/s. The solution has the form w(c)=max(ε, b0+b1*z(c)). Sorting arm predictions and cumulative first/second moments identifies the active prefix or suffix in O(m log m) time, where m is the arm size. Each candidate solves the two equality equations, checks the affine active/floor inequalities, then verifies actual normalized mass and standardized-prediction residuals at most 1e-8. 

R = N - m*epsilon
q = (N*mean_cohort(z) - epsilon*sum_arm(z)) / R
require q within [min_arm(z), max_arm(z)]
For a candidate nonfloor prefix or suffix S+:
[k, sum(z); sum(z), sum(z*z)] @ [b0,b1] =
    [N-epsilon*(m-k), N*mean_cohort(z)-epsilon*sum_inactive(z)]
w = max(epsilon, b0+b1*z)

Constant-arm predictions are feasible only when the same constant matches the whole-cohort target; the canonical extension is uniform N/m. At an extreme-tie boundary, all excess mass R is shared equally among tied extreme predictions and all other arm rows receive the floor. The canonical affine extension equals the floor at the nearest nonextreme prediction. A target outside the floor-adjusted arm convex hull, or no numerically valid candidate, yields no estimate.

The same training-fitted centering, scaling and affine-positive function are evaluated on heldout rows. There is no heldout re-fit or re-normalization, no target trimming and no posthoc repair of equality constraints. Heldout weights are not globally upper-bounded; concentration diagnostics still matter. Exact balance of one fitted prediction is not balance of all covariates or all functions, and does not certify a correct density ratio or positivity.

Previous UCA-style IPW implementation

The former finite-dictionary RN and later minimum-variance IPW weight fits are not the selected IPW routine anymore. General-ID kernel integration below is a separate path; it has not been relabeled as these new weights.

IPW: actual XGBoost joint propensity

For a requested whole treatment assignment a, the propensity is p_a(c)=P(A_tuple=a | C=c). A scalar treatment is a one-member tuple. All observed ordered tuples form one lexicographic class codebook. Correlated treatment members are learned jointly: the code never multiplies independently fitted marginal probabilities.

Each outer fold trains one actual XGBoost 2.1.4 classifier on every original training row and its whole joint-assignment label, using the same fixed64/depth3/eta.05/hist/nthread1/lambda1/min_child_weight5/subsample1/colsample1 settings. Two classes use binary:logistic (the other probability is its complement); more than two use multi:softprob with the recorded class count. Every stored class must occur in each training fold; no rare class is pooled or omitted. Class frequencies are not rebalanced or oversampled, and no outcome values enter fitting. Binary base_score remains the outer-training class1 prevalence. For more than two classes, each outer fold computes its own class-prior vector from training treatment labels only and repeats its natural logarithms in the fixed class-codebook order as base_margin on both training and prediction matrices. The softmax of these initial logits equals the training class priors; this margin overrides the common base_score=0.5, which is not the effective initial probability vector. Heldout class frequencies, outcomes and query assignment do not choose the offset. Actual class counts, priors, log-prior offsets, override flag and matrix scope are recorded per fold. No clipping or weight renormalization is added; finite-round learning can still leave imperfect probability estimates and weight mass. See the pinned official XGBoost2.1.4 intercept and base-margin documentation.

The heldout probability matrix must match the stored class order/shape, contain finite probabilities in[0,1] and sum to1 per row within1e-6. Every requested class probability is checked on the entire heldout cohort. A strictly positive value below1e-6 adds a warning and computation continues without modification. A zero or nonfinite probability, or a nonfinite inverse, returns a specific failure reason. There is no clipping, probability renormalization, prevalence stabilization or Hájek denominator. The inverse weight is exactly 1/p_hat_a(c).

The implementation supports at most32 observed joint classes as a computation limit, not a causal-identification theorem. Fewer than32 training rows or8 weighted heldout rows per requested class add warnings; those numbers are diagnostics, not minimums for computation. Absent requested assignments or empty training data needed by the selected estimator return a specific reason, even if each member's marginal assignment is observed. Finite discrete binary treatment coordinates are required; continuous observed values are never silently turned into class labels. CSV tuples use the existing100physical-column/500000cell budget. Generated binary clusters use the existing public2–8 vector shape and actual binary mechanisms; nodes[].members names the ordered output columns.

Folds, seeds and isolation

A seeded permutation within every observed joint treatment class allocates rows alternately to two outer folds. Class codebook, split and propensity seed do not depend on which assignment is queried. The data adapter derives the split seed as data_seed XOR 0x5A5A5A5A. Outcome-model seeds remain (split_seed+104729*(heldout+1)+1009*(class_index+1)) mod 2^32; scalar binary AIPW/OR retain their previous arithmetic and seed allocation exactly. Propensity-model seeds are (split_seed+104729*(heldout+1)) mod 2^32. No heldout outcomes or benchmark/model truth enter learning.

Complete ATE outcome/direct-weight fit counts are4/4 for AIPW and4/0 for OR; APO counts are2/2 and2/0. IPW makes0 outcome fits,0 direct-weight-solver fits and2 propensity-classifier fits for either estimand, always on all training classes. used.weights=true for IPW means derived inverse propensities are consumed; direct_weight_solver=false and fit_calls.weights=0 explicitly distinguish them from fitted balance weights. fit_calls counts actual attempts, fit_completed completed fits and fitted becomes true only when all required fits finish. An identical-regime ATE returns zero without fitting; APO is not a contrast against a zero reference.

Choose ATE or APO before estimating

Average Potential Outcome (APO) is the mean outcome under one requested intervention, E[Y(a)]. Average Treatment Effect (ATE) is the contrast E[Y(a)]-E[Y(a0)]. The requested estimand is stored in the result, options, query and copied code. It does not change the original target cohort or retained rows. 

For one requested assignment a:
OR:   s(a) = m_a(C)
AIPW: s(a) = m_a(C) + I(A_tuple=a)*w_a(C)*(Y-m_a(C))
IPW:  s(a) = I(A_tuple=a)*Y/p_hat_a(C)
APO = mean_n(s(a))
ATE = mean_n(s(a)-s(a0))

Outcome Regression (Plug-in)

Fits XGBoost means only for the requested assignment(s). APO never requires a counterfactual reference class or its outcome fit/support. It runs no weight feasibility, ESS or balancing solver checks.

IPW

Uses raw weighted outcomes, without a fitted outcome model or residual correction. The denominator is the original total n. Its classifier still learns all training treatment classes when only one APO arm is requested, but score/support checks concern the requested arm(s). ATE uses the same two fold classifiers as its two APO components. No independent-member probability product is substituted.

API: estimand="ate", summary="mean_difference" requires matching intervention/reference action names. estimand="apo", summary="mean" omits reference; a stale non-null reference is rejected. Assignment arrays follow the explicit stored member order. Explicit baseline methods on unsupported Front-door/Sequential/general graphs abstain, while compatible auto graph-plug-in APO requests use the existing mean path. Nonancestor actions can still be pruned without editing graph/data. Under auto/legacy dispatch two empty ATE action maps return the same observed-mean zero contrast; explicit baseline requests may be unsupported when no applicable action remains.

AIPW arm diagnostics include actual duals, training objective, prediction mean/scale and range, mass/μ/KKT residuals and floor fractions. IPW instead reports actual joint classifier parameters/counts and minimum/maximum queried probabilities. Both weighted methods report heldout mass/ESS/share; no unused solver diagnostics are presented as fitted. ESS/share are engineering concentration diagnostics, not positivity or confidence certificates. Public warnings is a list of code/message plus fold, assignment and observed/reference values where relevant; the legacy warning string remains. Reference thresholds describe diagnostics, not computational cutoffs. Empty required training data, an undefined inverse, failed required fits/constraints, nonfinite output or deadline return UNKNOWN with a concrete reason; invalid/stale inputs raise validation errors.

No observed-data standard error or confidence interval is estimated for AIPW, OR, IPW or graph plug-in results. Exact training balance does not establish real-world assumptions, correct outcome learning or accurate heldout weights. No unconditional double robustness or finite-sample unbiasedness is claimed.

Graph adjustment plug-in: XGBoost means

_estimate_mean uses the verified minimum adjustment witness and two seeded, unstratified folds. Discrete treatments/covariates are matched as exact whole-node arms/strata. For each training stratum, requested continuous action values must lie inside its observed range; constant predictors must match. The requested neighborhood size remains k=max(8,floor(sqrt(n_train))). A small matched source adds a warning; actual k is capped only to the available positive source size, with requested_k/actual_k recorded. Constant contexts use the entire matched pool, as before. Empty required sources return their exact fold/stratum reason. Neighbors remain coverage diagnostics rather than the outcome regression.

Each learned conditional mean uses fit_xgboost_mean with the same fixed settings above. Each output coordinate has an actual booster. Zero or constant conditional predictors still call XGBoost with a constant feature; there is no silent empirical-mean regression substitute. Nearest-neighbor diagnostics use training mean/std scaling and warn when more than 5% of rows exceed three times their factual radius. No-action unconditional sample means/event rates remain direct empirical averages, not fitted regressions.

For event probabilities the learned outcome is the 0/1 event indicator with reg:squarederror; this approximation is not probability-calibrated or silently clipped. No balancing weights or augmented score are added. The old string legacy_knn is an API compatibility selector only.

General-ID normalized-kernel plug-in

This is a separate, approximate integration procedure for supported identified formulas. It is not baseline AIPW.

_estimate_uca_mean calls the graph analyzer with up to 2 seconds of the remaining budget, max_orders=256 and max_mc_unions=256. The query must be marked identifiable. Tian, WMC and MC are the implementation’s identification-producer labels; MC here is not a Monte Carlo sampler. It tries accepted complete producers in the order Tian, WMC, MC; MC also requires a complete indexed formula. Identification alone is insufficient: the estimator's compiler must support the particular formula.

_uca_schedule freshens summed slots and requires a directed acyclic schedule of normalized observational kernels. It accepts sums, products, observational probability kernels and the number 1. It rejects ratios, unexpanded Q kernels, extraction operators, addition, unresolved/cyclic slots or duplicate suppliers. Limits are 2,000 visited expression nodes, depth 96 and 64 kernels. A formula may be available for display but unavailable for this numerical compiler.

There are two seeded, unstratified folds. Conditional kernels use exact discrete context matching in the opposite training fold, with requested k=max(8,floor(sqrt(n_source))). Small positive pools add warnings and cap k to available source rows; requested_k/actual_k and the reason are disclosed. Empty exact-match sources return a specific reason. Continuous context features use source-group means/standard deviations; values with standard deviation ≤ 1e-12 are treated as constant and must match the query. Neighborhood weights are uniform and normalized to sum to one.

Unconditional kernels use the heldout evaluation fold's empirical marginal. They do not fit a conditional regression on the opposite fold. Unconditional terminal stages use the heldout empirical source mean. Conditional terminal stages use actual XGBoost models trained on the opposite fold, including constant-context cases; their fit diagnostics are returned. If a generated head is used as a later context, or the request is an event probability, it draws an entire source/neighbor row uniformly, preserving coordinates of that head. Later kernels consume those generated values. The final targets or joint-event indicators are averaged across both folds, using the observed number of integration rows rather than the model-reference draw count.

For continuous contexts, the code records off-range queries and neighbor-radius coverage. A fixed intervention outside its training context range is allowed by default via allow_continuous_extrapolation=True, flagged as extrapolated. Setting it false withholds the approximation. Constant-context mismatch still fails. Coverage warns if any kernel/fold has more than 5% off-range queries or a radius above three times its median matched-factual radius. Nonfinite values, magnitude above 1e150 in checked matrices, sparse exact contexts and time/compilation limits withhold results.

The nonterminal conditional row-sampling/density kernels are unchanged; only learned terminal conditional means use XGBoost. There is no fitted propensity model, inverse-weight correction, balancing loss, AIPW augmentation or observed-data uncertainty estimate here. Bias and integration/smoothing error remain possible.

Random configurations and treatment members

Random Data can generate a real binary treatment vector with 1–4 members, alongside 1–50 continuous baseline covariate coordinates. Each treatment member has its own 0/1 assignment in the requested intervention; ATE additionally supplies a complete reference assignment, while APO supplies none.

The Outcome model menu reuses exactly three existing generator families: Linear outcome (linear) adds coefficient-weighted parent coordinates and noise; Binary outcome (binary) draws a 0/1 outcome by comparing a seeded uniform innovation with expit of the affine parent predictor plus noise; Neural Outcome (neural_network) passes all parent coordinates through a fixed dense NumPy network and adds scalar noise. Its model seed draws the depth (1–6), width (4 or 8), tanh/ReLU activation, weights and biases once; generation does not train the network. The data seed fixes its sampled noise and rows. The default setup uses linear X, binary A and Normal noise. The Outcome picker synchronizes Y family/type and selects Normal noise, preserving advanced edits to the X mechanism. Resolved model metadata records the actual function and parameters. These generation mechanisms are separate from the XGBoost nuisance models learned during estimation. Binary outcomes have model APO in [0,1] and model ATE in [−1,1]; raw finite-sample IPW estimates are not clipped into these intervals. Binary and Neural model references use the actual generated mechanisms, with Monte Carlo error where applicable. The graph remains the supplied causal assumption.

Each vector output reuses the existing scalar family per coordinate. Vector noise uses the generator's fixed dense mixing matrix; this is neither a new independent-treatment sampler nor a guarantee about conditional dependence for every seed. Model seed fixes mechanisms, coefficients and noise laws; data seed fixes rows from that model. The resolved model, ordered physical columns and snapshot IDs record what actually ran.

Changing a configuration, dimension or generation seed requires Generate data before estimation. Head, Download CSV, selected ATE/APO and Copy reuse that generated sample. An intervention such as A=(1,0,1) uses the recorded member order. IPW learns the whole tuple's joint propensity; it does not multiply independently fitted marginal propensities. Higher dimension can leave an assignment poorly represented: small class counts, small positive probabilities and concentrated weights now add warnings. Actual missing training data, undefined/nonfinite computations or deadlines still return a specific reason. The interface offers up to four treatment members; the underlying public builder retains its existing dimension limit of eight and its separate support rules.

Generated-model reference and Monte Carlo error

A Random Data reference evaluates the fixed simulated Structural Causal Model (SCM), a collection of generated mechanisms and noise laws. It is not learned from the observed sample.

sample_reference is a separate action requiring a current Random Data model token, sample ID, public graph and any active random-binding key. It is unavailable for uploaded CSVs. It uses the same fixed mechanisms without replacing or modifying stored observed rows. Its seed is the observed data seed XOR 0xA5A5A5A5, distinct from the nuisance split seed.

Verified scalar linear expectation

_reference can propagate analytic means through eligible scalar linear mechanisms without factual evidence. It checks the actual generated function identity, coefficients, parent set and supported Normal/Uniform noise mean. If every required ancestor passes, approximate=False and reference_kind="exact_model_mean" identify an analytic model answer. This is not a claim that the real-world causal effect is known.

Explicit-vector intervention sampling

The bounded Random vector adapter uses the existing sample_interventional method. APO samples one requested intervention world and averages Y; its Monte Carlo standard error (MCSE) is sd(Y)/sqrt(n), with ddof=1. ATE samples two intervention worlds of the same model using the same per-variable exogenous random streams and averages their paired outcome differences; its MCSE is sd(Y(a)−Y(a0))/sqrt(n). approximate=True and reference_kind="monte_carlo_model_mean" distinguish this from an exact answer.

Reference draws are 256–10,000 and separately requested from the observed Records count. Defaults are 512 when a random cluster exceeds dimension 8; otherwise at least 2,048 or the observed row count, subject to request validation. The one APO frame or the two ATE frames together are limited to100 physical columns and500,000 cells; the budget uses the actual world count. Time/nonfinite/shape failures expose no partial reference value.

Advanced SCM query path

Outside the verified analytic branch, the original SCM.query uses generated-model Monte Carlo. With factual equality evidence it uses sequential residual likelihood weighting and shared binary innovation thresholds; it does not learn nuisance regressions from the CSV. It normalizes particle evidence weights, requires ESS ≥ 100 and maximum particle share ≤ 0.1, and can reject unsupported custom mechanisms/densities or unresolved event thresholds. Those particle weights are different from AIPW's learned correction weights.

The original SCM path reports simulation standard errors from its actual particle calculations. The paired-vector path reports MCSE for its paired draws. Neither is a confidence interval or standard error for the observed-data effect estimate. A larger simulation draw count reduces simulation error; it does not repair confounding, nuisance bias or sparse observed support.

Exact source and retained-data reproduction

Each result records the real method, source SHA256, callable, method selection, source-column/full-one-hot recipes, seed, contrast and fixed options. Copy verifies the fetched source SHA. Baseline standalone code contains the entire actual numerical module, including the XGBoost helper, and calls estimate_balancing_aipw(..., estimator=options.estimator, estimand=options.estimand) on the retained factual CSV. It needs pip install numpy scipy xgboost==2.1.4. It never regenerates rows or uses a reference. A pasted notebook can run; unavailable source fingerprint is explicitly null.

Graph plug-in replay uses the actual graph, mapping, encoding, data seed, query and method selector with Editor.request("load_data", ...) and Editor.request("estimate_data", ...). The package includes both the adapter and its imported XGBoost helper. Small floating-point differences across native/WASM builds are possible, even with the same pinned version and fixed single-threaded settings.

Source grounding and limits

  • Official XGBoost train API; actual pinned Pyodide package lock
  • Zubizarreta: Stable Weights that Balance Covariates for Estimation with Incomplete Outcome Data (related minimum-variance balancing)
  • Chernozhukov et al.: Double/debiased machine learning (related augmented scores and cross-fitting)

The user's scalar fitted-outcome constraint, fixed XGBoost settings, positive-floor affine extension and engineering gates are this product's actual specialization. This is not a claim to implement a cited paper's full algorithm or guarantee. Conditional double robustness and inference theorems need assumptions and learning-rate conditions that this tool does not certify from data. Good training balance alone does not establish overlap, a correct causal graph, finite-sample unbiasedness or a confidence interval.
